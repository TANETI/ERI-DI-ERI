# ERI DI-ERY Phase 3.0 — 스케줄 변경 이력

전체 프로젝트의 다음 핵심 단계로,
급여·체중 일정이 바뀌어도 과거 달력과 보고서가 다시 쓰이지 않도록
**스케줄 변경 이력**을 실제 계산에 연결했습니다.

## 에리 이스터에그 미세 조정

요청 반영:
- 이동 속도: 기존 260ms → **312ms**
- 좌우반전 주기: 기존 96ms → **116ms**

둘 다 약 20% 느려졌습니다.
이동 벡터를 향해 고개를 돌리는 동작은 그대로 유지됩니다.

## 급여 스케줄 변경 이력

기존:
- 설정의 현재 `2일마다 / 21:00 / 새벽 06시` 한 값으로
  과거 날짜까지 다시 계산

변경:
- 설정을 바꿀 때 `적용 시작일` 기준으로 새 기간 추가
- 이전 기간은 그대로 보존
- 같은 적용 시작일로 다시 저장하면 그 기간만 수정

예:
- 8/31부터 2일마다
- 9/15부터 3일마다

이면 9/14 이전 달력/보고서는 계속 2일 주기로 계산되고,
9/15 이후만 3일 주기를 사용합니다.

각 기간은:
- 적용 시작일
- 급여 간격
- 기본 시간
- 다음 날 새벽 인정 마감

을 함께 기억합니다.

## 체중 일정 변경 이력

체중도 첫 실제 측정일을 기준으로 기간을 만들고,
이후 **측정 간격만 바꾸면 설정을 저장한 날짜부터** 새 적용 기간을 추가합니다.
첫 측정일 필드는 잘못된 시작점을 수정할 때만 사용합니다.

과거 측정 예정일은 새 주기로 다시 밀리지 않습니다.

## 지연된 체중 측정

예:
- 예정일 9/15
- 실제 측정 9/16

이 경우:
- 9/15 회차의 늦은 측정으로 인정
- 다음 일정 자체는 9/16 기준으로 밀리지 않음
- 원래 스케줄 anchor 유지

오늘까지 미측정 회차가 남아 있으면 홈에서
`체중 측정 지연`으로 가장 오래된 미완료 예정일을 보여줍니다.

## 달력 / 보고서

- 과거 달력: 그 날짜에 적용되던 급여 정책 사용
- 새벽 급여 매칭: 당시 새벽 인정 마감 사용
- 보고서: 스케줄 이력 목록 포함
- 급여 예정 횟수: 기간별 정책으로 계산
- 날짜별 상세 기록: 당시 적용 정책 표시

기존 보고서의
“현재 설정만 사용하므로 과거 정책 변경이 반영되지 않는다”
문구도 제거했습니다.

## 기존 데이터 마이그레이션

현재 사용 중인 설정은 자동으로 첫 번째 역사 기간으로 변환됩니다.

기존:
- feedingStartDate
- feedingIntervalDays
- feedingTime
- feedingGraceUntilHour
- weightStartDate
- weightIntervalDays

값은 그대로 유지되며,
처음 실행할 때 이 값들로 이력 배열을 만들어 사용합니다.
